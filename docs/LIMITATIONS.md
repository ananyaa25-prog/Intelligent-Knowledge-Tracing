# Limitations

1. **Tiny evidence per topic.** A session has 14-17 questions over 5-10 topics, so 1-4 answers per topic. Statuses and "ready" flags rest on very little data. In simulation, exact status accuracy was only about 46-53% (within one step about 93-94%), ready-for-next flags were right only 32-60% of the time, and only 40-47% of the 10 topics reached the minimum of 2 answers (reports/simulation_notes.md).
2. **Synthetic evaluation.** The policy comparison uses synthetic students whose answers follow a simple logistic ability model, not the model's training distribution. It validates the decision logic (which levels get served, how statuses are assigned), not real learning and not knowledge-tracing accuracy. The demo combination (model policy + calibration + core5) was checked end-to-end but not re-simulated as a combination.
3. **Domain shift (ASSISTments 2009 -> generated quiz).** The model was trained on ASSISTments problems; the quiz uses procedurally generated template questions mapped to the same skill ids. Template Easy/Medium/Hard only approximate the data-derived difficulty buckets (per-skill tertiles of training success). Calibration and monotonicity were measured on ASSISTments validation data, not on quiz answers.
4. **Thresholds are design choices.** T_PROF = 0.70, T_READY = 0.60, MIN_ANSWERS = 2, TARGET_P = 0.70 and the target band 0.55-0.85 are reasonable conventions, not values fitted to outcomes. They are configurable (policy_config.py) and were not tuned after seeing results.
5. **No learning-outcome or teacher study.** Nothing here shows that students learn more or that teachers act better. There is no pilot data yet (reports/pilot.md: 62 usable answers, but almost all from developer/tester sessions (ids such as 10, 12, 88109-ak), not a pilot sample). No teacher has been interviewed.
6. **Small model gain.** The gated model beats DKT-only by +0.0035 validation AUC (0.8950 vs 0.8915, mean of 3 seeds); the graph alone did not help (0.8900).
7. **Topic selection and the model.** Picking the topic with the lowest *model* prediction kept returning to topics the student had answered correctly, because the model's per-topic estimates are dominated by recent answers on any topic (reports/answer_response.md). The demo therefore blends in the student's own record (D31, added after user testing, not pre-registered). With the original rule the staircase served Easy only 2% of the time in simulation; with blending, 23%.
8. **Model behaviour on unseen topics.** For a topic the student has not answered yet, the model's estimate is unreliable (about 0.97 at Easy before the first answer). The first question on a topic under the model policy is therefore Medium; the displayed percentage for a probe or a first question should be read with care. A pending question is lost if the service restarts mid-question.
9. **Post hoc changes.** The model-policy level rules (D27), the cautious evidence-conflict rule (D30), cross-session history (D28) and blended topic selection (D31) were introduced after a user test and dry runs, i.e. after seeing results. They are documented, and the simulation was re-run; Gate S was then applied as pre-registered and failed. Earlier adaptive sessions were back-filled as completed (scripts/backfill_completed_sessions.py).
10. **Exclusion by id pattern.** Analytics exclude ids matching `(smoke|e2e|pred_check|test|^sim_)`. This also excludes real ids that contain "test" (e.g. "contest"), and it cannot catch test accounts with other names: the existing live DB contains developer accounts such as `10`, `demo_student_qa` and `dash_st_*` that are not excluded.
11. **Legacy tests.** 15 pytest tests and 3 Node smoke suites written for the old fixed 10-question flow failed before this work and still fail; they were not rewritten.
12. **Recency-driven estimates.** The knowledge-tracing state is dominated by the most recent answers on any topic, so a run of wrong answers on one topic lowers the estimates for all topics. The profile corrects only clear contradictions with a topic's own answers (one step; docs/DECISIONS.md D26); smaller distortions remain.
13. **Privacy.** Student ids are free text; there is no authentication. Use pseudonymous ids (docs/PILOT_GUIDE.md).
